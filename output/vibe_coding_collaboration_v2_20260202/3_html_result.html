협업의 위기

속도의 패러독스

개별 구현 속도 ↑ 그러나 팀 통합 속도 ↓ — AI 도입 후 코드 중복 최대 8배 증가

의미론적 충돌 (Semantic Conflict)

AI가 동일 기능을 다른 로직으로 생성

→ 머지 시간 폭발적 증가

기술적 사재기 (Technical Hoarding)

기존 유틸리티 인식 못하고 새 함수 생성

→ 코드 중복 8배 증가

LGTM 리플렉스

AI 코드가 외견상 완벽해 검증 소홀

→ 보안 취약점이 프로덕션 반영

맥락 파편화

제한된 컨텍스트 윈도우로 지식 공유 불가

→ 코드베이스 엔트로피 증가
해결책: 바이브 엔지니어링(Vibe Engineering) — 단순 '바이브'를 넘어 체계적 거버넌스로 전환 필수

AI 에이전트 규칙 표준화

.cursorrules, CLAUDE.md를 '살아있는 문서'로 관리하여 팀 표준 이식

필수 규칙 파일

  • .cursorrules / CLAUDE.md

    AI의 '영구적인 뇌' 역할, 팀 합의사항 명시

  • PLAN.md

    구현 전 계획 문서화, 팀원 사전 승인 요구

  • 공용 프롬프트 라이브러리

    검증된 템플릿 공유로 동일 수준 AI 출력 보장

규칙 예시

  • 1
    기술 스택 제약

    "Redux 대신 Zustand 사용", "Tailwind CSS만 허용"

  • 2
    복잡도 제한

    "파일당 300라인 초과 시 모듈 분리"

  • 3
    보안 정책

    "API 키 하드코딩 금지", "Zod로 입력 검증"

핵심: 규칙 파일은 고정 문서가 아닌, AI 실수 발견 시 즉시 업데이트하고 Git으로 공유하는 '살아있는 문서'
